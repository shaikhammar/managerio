# Phase 3.4 — Client Portal (Read-Only)

**Date:** 2026-04-02
**Status:** Approved

---

## Overview

A public-facing client portal providing three read-only surfaces accessible via signed URLs, with no authentication required. The portal covers quote approval, invoice viewing with PDF download, and project status checking.

---

## Decisions Made

| Question | Decision |
|---|---|
| Token mechanism | Laravel signed routes (`URL::signedRoute`) — no DB columns, validated by `signed` middleware |
| Quote approval | Status change + optional comment + email notification to business |
| Invoice portal | View details + PDF download |
| Project status | Status only — name, status badge, deadline, source/target languages |

---

## Architecture

### Route File

A dedicated `routes/portal.php` registered in `bootstrap/app.php` alongside `routes/web.php`. Routes live outside the `auth` middleware group but are protected by the `signed` middleware.

```php
// routes/portal.php
Route::middleware(['signed'])->prefix('portal')->name('portal.')->group(function () {
    Route::get('/quotes/{quote}', [QuotePortalController::class, 'show'])->name('quotes.show');
    Route::post('/quotes/{quote}/approve', [QuotePortalController::class, 'approve'])->name('quotes.approve');
    Route::post('/quotes/{quote}/reject', [QuotePortalController::class, 'reject'])->name('quotes.reject');

    Route::get('/invoices/{invoice}', [InvoicePortalController::class, 'show'])->name('invoices.show');
    Route::get('/invoices/{invoice}/pdf', [InvoicePortalController::class, 'pdf'])->name('invoices.pdf');

    Route::get('/projects/{project}', [ProjectPortalController::class, 'show'])->name('projects.show');
});
```

### Controllers

`app/Http/Controllers/Portal/` — three focused controllers, no auth, no business middleware.

- `QuotePortalController` — show quote details; handle approve/reject with optional comment
- `InvoicePortalController` — show invoice details; stream PDF download
- `ProjectPortalController` — show project name, status, deadline, language pairs

### Services

Signed URL generation added to existing service classes:

- `QuoteService::generatePortalUrl(Invoice $quote): string`
- `InvoiceService::generatePortalUrl(Invoice $invoice): string`
- New `ProjectPortalService` — `generatePortalUrl(Project $project): string` and (later) other project portal concerns

Quote approval/rejection logic lives in `QuoteService`:
- `approveFromPortal(Invoice $quote, ?string $comment): void`
- `rejectFromPortal(Invoice $quote, ?string $comment): void`

### Mailable

`App\Mail\QuotePortalResponseMail` — sent to the business's `smtp_from_email` when a client approves or rejects. Includes quote number, client name, decision, comment, and a direct app link back to the quote. Implements `ShouldQueue`.

### Event

`App\Events\QuoteRespondedFromPortal` — dispatched after status change. A listener `SendQuotePortalResponseNotification` sends the mailable if SMTP is configured.

---

## Data Model Changes

### Migration: `add_portal_comment_to_invoices_table`

Adds `portal_comment` (`text`, nullable) to the `invoices` table. Stores the client's free-text comment submitted alongside an approval or rejection.

No other schema changes. Signed URLs are stateless — no token columns required.

## Frontend Pages

All portal pages use a minimal public layout (`PortalLayout`) — no sidebar, no auth chrome, just the business name/logo, the document, and action buttons.

| File | Purpose |
|---|---|
| `resources/js/pages/portal/quote-approval.tsx` | Quote details, approve/reject form with optional comment textarea |
| `resources/js/pages/portal/invoice-view.tsx` | Invoice line items, totals, due date, status badge, PDF download button |
| `resources/js/pages/portal/project-status.tsx` | Project name, status badge, deadline, source/target languages |
| `resources/js/layouts/portal-layout.tsx` | Shared wrapper: business logo/name, clean minimal header |

### "Copy Portal Link" UI

A **Copy Portal Link** button (clipboard icon) is added to the existing `show` pages for quotes, invoices, and projects. It calls a backend endpoint that returns the signed URL, then copies it to clipboard. No automatic email sending — the PM shares the link as they see fit.

Routes for generating portal links (auth-protected, inside the business middleware group):
```
GET /{business}/sales/quotes/{quote}/portal-link    → QuoteController@portalLink
GET /{business}/sales/invoices/{invoice}/portal-link → InvoiceController@portalLink
GET /{business}/translation/projects/{project}/portal-link → ProjectController@portalLink
```

## Quote Approval Flow

```
1. PM copies portal link from quote show page
2. Client opens signed URL → QuotePortalController@show
3. Page renders: quote lines, totals, approve/reject buttons, optional comment field
4. Client submits → POST portal/quotes/{quote}/approve (or /reject)
5. QuoteService::approveFromPortal / rejectFromPortal:
   a. Validates quote is still in SENT status (guard: already approved/rejected quotes return error)
   b. Sets status → APPROVED or CANCELLED
   c. Stores portal_comment on the invoice
   d. Dispatches QuoteRespondedFromPortal event
6. Listener sends QuotePortalResponseMail to business SMTP (if configured)
7. Client sees confirmation page: "Thank you — your response has been recorded."
```

**Guard:** If the quote is already in `APPROVED` or `CANCELLED` status, the portal shows a read-only "This quote has already been responded to" message.

## Error Handling

| Scenario | Behaviour |
|---|---|
| Invalid/tampered signature | Laravel auto-returns 403 (InvalidSignatureException) |
| Quote already responded to | Show read-only confirmation message, no form |
| Invoice is void | Show "This invoice is no longer active" message |
| SMTP not configured | Approval still proceeds; email silently skipped (logged) |
| Quote not found | 404 |
