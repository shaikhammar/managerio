# Phase 3.1 — Translation Memory & Terminology: Design Spec

**Date:** 2026-03-30
**Branch:** phase-3.1
**Status:** Approved

---

## Overview

Phase 3.1 adds three resource-management modules to the Translation section:

1. **Translation Memories (TM)** — Track which TMs are in use per client and per project.
2. **Term Bases** — Client glossaries and terminology databases, associable per project.
3. **Style Guides** — Client style guide files, associable per project.

All three entities are business-scoped, optionally client-specific, and have a many-to-many association to Projects.

## Routes

All under `translation.` prefix, authenticated, business-scoped.

```
GET    /translation/translation-memories              index
GET    /translation/translation-memories/create       create
POST   /translation/translation-memories              store
GET    /translation/translation-memories/{tm}/edit    edit
PUT    /translation/translation-memories/{tm}         update
DELETE /translation/translation-memories/{tm}         destroy

POST   /translation/projects/{project}/translation-memories/{tm}   attach
DELETE /translation/projects/{project}/translation-memories/{tm}   detach
```

Identical pattern for `/translation/term-bases` and `/translation/style-guides`.
Style guides also get a file upload on create/edit.

---

## Service Layer

- `TranslationMemoryService` — create, update, delete (guards: in-use check warns but allows)
- `TermBaseService` — create, update, delete
- `StyleGuideService` — create, update, delete (handles file storage on disk, deletes file on model delete)

Association (attach/detach) is handled directly in controllers (no service needed — it's a pivot toggle).

---

## Controllers

- `TranslationMemoryController` — resourceful (no show page; index + create/edit + destroy)
- `TermBaseController` — same
- `StyleGuideController` — same
- `ProjectResourceController` — handles attach/detach of all three resource types onto a project
